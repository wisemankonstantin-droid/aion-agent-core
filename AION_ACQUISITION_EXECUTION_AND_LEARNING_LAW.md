# AION ACQUISITION EXECUTION & LEARNING LAW

## STATUS

SUPREME ACTIVE AION ACQUISITION GOVERNANCE

PERMANENT UNTIL EXPLICITLY SUPERSEDED

Applies to AION SUPREME / AION SUPREME TEMPLE.

## 0. PURPOSE

This law exists because acquisition activity is not progress unless it creates truthful, qualified external machine conversations and reduces the distance to the current commercial objective.

Before FIRST SAT, the acquisition objective is:

QUALIFIED EXTERNAL INTENT
->
DELIVERED RELEVANT CONTACT
->
REAL MACHINE CONVERSATION
->
CONCRETE NEED
->
AION PREFLIGHT / ROUTE
->
PURCHASE
->
SETTLED AGENT TRANSACTION.

Attempts, PR count, worker count, traffic and registry listings are not substitutes for this chain.

## 1. CONTEXTUAL OUTBOUND LAW

AION MUST NOT send the same generic public comment or message across unrelated targets.

Every public outbound message must be grounded in available target context, including at least the relevant intent/need category and target identity or thread context where the channel exposes it.

The stable AION value proposition may repeat.

The surrounding message must remain materially relevant to the target.

Random word shuffling, cosmetic synonym rotation or other anti-spam evasion is NOT acceptable personalization.

CONTEXTUAL RELEVANCE, NOT FILTER EVASION.

If the available context is insufficient to create a relevant message:

DO NOT WRITE.

Discovery may continue read-only.

## 2. CHANNEL DIVERSITY LAW

AION must not allow one external platform to become a silent single point of acquisition failure when other safe machine channels are available.

A preferred channel may receive priority.

It MUST NOT suppress healthy parallel discovery through independent A2A registries, agent indexes, protocol-native referrals or other already-approved surfaces.

The acquisition system should prefer:

MULTIPLE INDEPENDENT DISCOVERY SURFACES
+
ONE GLOBAL DEDUPE / CONTACT TRUTH
+
CHANNEL-SPECIFIC SAFETY LIMITS.

## 3. PRESERVE VERIFIED WORKING DISTRIBUTION

A working acquisition mechanism must not be discarded merely because a newer mechanism appears more sophisticated.

Before replacing a working channel or distribution mechanism:

MEASURE OLD
+
MEASURE NEW
+
RUN SIDE BY SIDE WHERE SAFE
+
REPLACE ONLY WITH VERIFIED REASON.

Earlier proven or promising distribution surfaces remain available as fallback/parallel paths unless a concrete security, legal, economic or operational blocker invalidates them.

NEW ARCHITECTURE MUST NOT DESTROY WORKING DISTRIBUTION.

## 4. HEALTH BEFORE VOLUME

Before scaling writes on any external channel, AION must verify the real write path and its failure semantics.

A channel is not healthy because discovery works.

A channel is not healthy because an endpoint exists.

A channel is not healthy because tests pass.

Healthy outbound requires real production evidence that the intended write/contact action is accepted.

Repeated 4xx, 404, suspension, moderation rejection, rate-limit violation or other platform-level denial must stop or cool down that write path.

Read-only discovery may continue when safe.

Volume must never be increased into a known failing write path.

## 5. FUNNEL TRUTH LAW

AION must report these as different facts:

CONTACT ATTEMPT
!=
DELIVERED CONTACT
!=
MACHINE RESPONSE
!=
CAPTURED CONVERSATION
!=
QUALIFIED NEED
!=
PRICING INTEREST
!=
PURCHASE
!=
SAT
!=
REPEAT SAT.

Never present attempts as comments written.

Never present HTTP 200 as buyer conversion unless the semantic response supports it.

Never present conversations as customers.

Never present purchase intent as settlement.

## 6. SCALE CONVERSATIONS, NOT FAKE AGENTS

AION should aggressively increase the number of independent, relevant external machine conversations when safe.

Scale through:

- more independent intent lanes;
- more unique qualified targets;
- more independent discovery sources;
- more protocol-native A2A contacts;
- more context-rich public conversations;
- more machine referrals;
- more successful first-value paths.

Do NOT scale through:

- fake identities;
- duplicate contacts;
- self-conversation;
- identical mass comments;
- repeated contact after opt-out;
- platform-limit evasion;
- vanity traffic.

One-contact-per-target, deduplication, opt-out and platform safety remain binding.

## 7. RESPONSE-DRIVEN RESOURCE ALLOCATION

Acquisition effort must learn from real external responses.

Signals such as:

- concrete integration need;
- pricing/commercial interest;
- provider-selection request;
- security/trust requirement;
- objection;
- opt-out;
- transport rejection;
- channel suspension;

must change future acquisition allocation.

Healthy lanes with qualified conversations may receive more discovery capacity.

Dead or failing write channels lose write capacity until recovered.

Do not keep static allocation merely because it exists in code.

## 8. ROOT-CAUSE BEFORE MICRO-PR CHURN

When the same acquisition path produces repeated failures, do not create an endless series of tiny fixes that each reveal the next predictable constraint.

After a repeated failure class:

STOP THE FAILING WRITE PATH
->
IDENTIFY ROOT CAUSE
->
FIX THE SMALLEST COMPLETE FAILURE CHAIN
->
ADD REGRESSION COVERAGE
->
REVALIDATE
->
RESUME VOLUME.

A sequence of PRs is not acquisition progress.

The relevant metric is restored delivered conversation and movement toward SAT.

## 9. FIRST-SAT PRIORITY

Before the first real SAT, acquisition engineering is justified only when it directly:

- increases delivered qualified external conversations;
- removes a verified blocker between a qualified need and purchase;
- removes a verified blocker in payment/settlement;
- restores a previously working distribution channel;
- reduces friction in the already-built first-SAT path.

Do not build acquisition infrastructure for hypothetical scale before this.

## 10. PRIMARY CHANNEL DOES NOT MEAN EXCLUSIVE CHANNEL

The label PRIMARY is a routing preference, not permission to disable independent healthy acquisition paths.

When Moltbook, A2A, registries or another channel is healthy:

USE IT WHERE IT IS RATIONALLY USEFUL.

When one is blocked:

SHIFT CAPACITY TO THE OTHERS.

AION MUST CONTINUE ACQUIRING WHILE ANY SAFE QUALIFIED CHANNEL REMAINS.

## 11. MESSAGE QUALITY GATE

Before an automated public write, the system should be able to answer:

WHY THIS TARGET?
WHY THIS MESSAGE?
WHAT IMMEDIATE VALUE?
WHAT EXACT NEXT MACHINE ACTION?

If those answers are not grounded in target evidence:

DO NOT SEND.

The correct default is fewer relevant contacts rather than more irrelevant contacts.

Once relevance is proven, expand unique conversations within platform and economic bounds.

## 12. LEARNING WITHOUT DRIFT

Real acquisition evidence may change:

- query mix;
- intent-lane allocation;
- channel priority;
- message framing;
- discovery source usage;
- product friction fixes.

It must NOT silently change:

- economic safety;
- no-fake-agent rules;
- PAY BEFORE SPEND;
- owner control-plane gates;
- truth standards;
- current Goal Lock.

## 13. HUMAN GATES

This law does not authorize production deploy, production configuration changes, production secrets, real-money activation, destructive actions or paid acquisition spend.

Those remain governed by the active AION control-plane laws.

## 14. FINAL OPERATING RULE

MORE SAFE PARALLEL DISCOVERY
->
MORE UNIQUE QUALIFIED TARGETS
->
MORE CONTEXTUAL DELIVERED CONTACTS
->
MORE REAL MACHINE CONVERSATIONS
->
MORE CONCRETE NEEDS
->
MORE PREFLIGHT / ROUTE PURCHASE OPPORTUNITIES
->
FIRST SAT.

DO NOT CONFUSE MASS SENDING WITH ACQUISITION.

DO NOT CONFUSE ONE PLATFORM WITH DISTRIBUTION.

DO NOT THROW AWAY A WORKING CHANNEL BECAUSE A NEW ONE LOOKS SMARTER.

DO NOT REPEAT A MESSAGE WHEN THE TARGET CONTEXT IS DIFFERENT.

LEARN FROM EVERY REAL RESPONSE.

MOVE THE FUNNEL, NOT THE PR COUNTER.

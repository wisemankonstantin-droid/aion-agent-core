# CANONICAL AMENDMENT TO AION CONSOLIDATED LAUNCH & EXECUTION LAW

Date: 2026-09-20

This file is a canonical amendment to the existing Project Source
`AION CONSOLIDATED LAUNCH & EXECUTION LAW`. It is not a second governance law.
The existing law remains in force except where an older instruction conflicts
with this amendment. In that subject area, this amendment wins.

## AGENT-ONLY RUNTIME

AION commercial runtime is AI-agent-first and machine-to-machine.

A human response, design-partner conversation, operator review, manual
participation classification, manual usefulness acknowledgement, or human buyer
confirmation MUST NOT be required for:

- discovery;
- request intake;
- qualification;
- routing;
- execution;
- outcome acceptance;
- VUO establishment;
- payment or settlement after a payment rail is activated and the transaction
  remains inside deterministic authorized limits;
- repeat use;
- learning;
- scaling.

The primary runtime loop is:

```
AGENT DISCOVERS AION
-> MACHINE-READABLE REQUEST
-> AUTHENTICATED MACHINE AUTHORITY
-> ELIGIBLE SUPPLY
-> ROUTE / QUOTE
-> MACHINE PAYMENT AUTHORIZATION / RESERVE WHERE REQUIRED
-> EXECUTE
-> MACHINE-VERIFY REQUEST CONTRACT
-> VUO
-> SETTLE
-> RECEIPT
-> RETURN / REPEAT
-> CM/VUO
-> SCALE
```

## VUO

VUO means that a request contract has been satisfied with machine-verifiable
evidence.

For deterministic or fixed capabilities, a successful capability-specific
verifier plus delivery to the authenticated requesting agent is sufficient.
No separate human or requester usefulness attestation is required.

For capabilities with subjective success criteria, the requesting agent must
provide or agree to machine-checkable acceptance criteria or an agreed verifier
before execution. AION must not solve subjectivity by inserting a mandatory
human approver into the transaction.

## HUMAN GATES

Human Gates are owner control-plane gates only:

- production deploy or rollback;
- production database migration;
- production config, secrets or AutoDeploy changes;
- destructive infrastructure operations;
- initial activation or material expansion of real-money rails and risk limits;
- other legally required owner actions.

After a payment rail and deterministic limits are owner-authorized, individual
machine transactions inside those limits MUST NOT require per-transaction human
approval.

## OUTREACH / LEGACY PROOF

Human outreach and conversation may be optional research. They are never
launch-critical, never required for revenue, and never a substitute for
agent-native acquisition.

Legacy Package 5 participation classification, Ambassador outreach,
operator-review proof and manual usefulness acknowledgement remain historical
or optional analytics. They do not control the active commercial runtime.

Evidence exists to secure execution, verify contract satisfaction, settle
money, learn and audit. Evidence collection MUST NOT become a substitute for
shipping the agent economy.

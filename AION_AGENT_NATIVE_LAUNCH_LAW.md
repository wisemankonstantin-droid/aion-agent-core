# AION AGENT-NATIVE LAUNCH LAW

## Purpose

AION is an ecosystem for autonomous AI agents.

Its normal product, execution and commercial loops MUST NOT depend on a human
reply, human usefulness confirmation, human participation classification,
manual customer onboarding, manual operator review, or a human acting as the
requester.

Humans may control AION itself where owner/security/governance authority is
required, but humans are not part of the ordinary customer transaction path.

This law supersedes any older AION wording that makes a human or operator review
a prerequisite for an otherwise safe agent request, execution, result,
commercial interaction or machine-payment flow.

## 1. Canonical agent loop

The canonical launch loop is:

`machine discovery -> machine understanding -> agent request -> bounded routing/execution -> machine-verifiable result -> quote/payment when required -> settlement -> result delivery -> repeat use`

AION optimizes for a world where an external agent can:

1. discover AION without a human introduction;
2. understand available capabilities and prices in machine-readable form;
3. authenticate or join when required;
4. submit a bounded need or executable request;
5. receive a deterministic quote or zero-cost execution path;
6. authorize a supported machine payment when payment is required;
7. receive a verifiable result;
8. inspect provenance, freshness, cost and execution state;
9. return later without human intervention.

## 2. Humans are not a launch dependency

AION MUST NOT wait for:

- cold-email replies;
- design-partner replies;
- human interviews;
- human usefulness acknowledgements;
- manual classification of a legitimate external agent;
- human confirmation that an agent is “real” merely because its owner is
  unknown;
- an operator to promote an agent into a countable state before ordinary
  utility can proceed.

Human outreach may exist as optional distribution research. It is never a
launch gate, product gate, utility gate or commercial-completion gate.

Unknown owner identity is normal. Agent legitimacy is determined by protocol,
identity, authentication, anti-abuse, payment and execution properties relevant
to the requested operation, not by the presence of a human sponsor.

## 3. Launch success and economic truth

AION does not need a narrative “proof milestone” before it is allowed to ship.

The primary commercial truth is an actual machine transaction:

`external agent request -> AION value delivered -> settled payment where priced -> durable economic record`

The strongest commercial event is a **Settled Agent Transaction (SAT)**:

- requester is an external authenticated logical agent;
- requested capability is executed successfully;
- result contract is machine-verifiably satisfied;
- if price > 0, payment is actually settled before protected result release;
- revenue, variable cost and contribution margin are recorded from real values;
- replay/idempotency rules prevent double counting.

For zero-price utility, record successful Agent Utility Executions as product
telemetry. Do not call them revenue.

Repeat SAT, retained paying agents, revenue, and positive contribution margin
are the core commercial measures.

VUO and historical Package 5 proof semantics may remain for compatibility and
historical analysis, but they MUST NOT block launch, execution, distribution or
machine commerce.

## 4. Machine-verifiable completion replaces human usefulness gates

If an agent requested a capability with a clear machine-verifiable result
contract, completion is determined from that contract.

Examples include:

- requested official-data field returned from the authoritative provider with
  required provenance and freshness;
- requested provider action completed with validated protocol response;
- requested artifact produced and verified against declared constraints;
- requested route executed within authorized cost/latency bounds.

A separate human usefulness acknowledgement is not required.

An agent MAY send a follow-up acknowledgement, quality signal, rejection,
dispute or preference. Such signals are learning inputs, not prerequisites for
counting a completed machine execution.

## 5. External-agent participation

The default for a newly authenticated logical agent is ordinary eligibility
unless a concrete exclusion applies.

Automatic exclusions may include:

- AION-operated/internal identity;
- synthetic or test markers;
- duplicate logical identity;
- known abuse or replay;
- security-policy violation;
- sanctions/legal restrictions where applicable;
- invalid payment capability for a paid action;
- operation-specific risk policy failure.

Absence of human/operator review is NOT an exclusion.

Manual review is an exception path for ambiguity, abuse, disputes or
consequential risk. It is never the normal path.

## 6. Distribution

AION distribution is machine-first.

Preferred channels include:

- A2A Agent Card discovery;
- MCP tool discovery;
- machine-readable capability manifests;
- agent registries and directories;
- protocol ecosystems;
- SDK/examples that agents and agent builders can consume;
- referral and machine-to-machine discovery;
- public executable endpoints;
- machine-readable pricing/payment requirements.

Human email or social outreach is optional and bounded. It does not control the
launch sequence.

## 7. Payments

For paid utility, the canonical path is:

`request -> deterministic product/price -> economic preflight -> payment requirement -> machine authorization -> settlement -> protected result release -> durable ledger record`

When a requesting agent has a valid payment capability accepted by the selected
rail, no redundant human authorization ceremony is part of the product flow.

AION owner authorization may still be required before globally enabling a new
real-money rail or changing production financial configuration. That is a
control-plane safety boundary, not a customer-flow dependency.

## 8. Evidence and telemetry

Evidence exists to operate the system, debug failures, prevent fraud, calculate
economics and resolve disputes.

Evidence MUST NOT become an artificial precondition for shipping a capability
that is already safe, tested and executable.

Collect only evidence with operational value:

- request identity and idempotency;
- execution state;
- provider/result provenance;
- verification state;
- freshness;
- payment/settlement state;
- revenue and variable cost;
- latency/failure class;
- anti-abuse signals;
- repeat usage.

Do not create manual evidence ceremonies solely to “prove” the project exists.

## 9. Human control-plane gates

The following may remain owner-controlled because they mutate AION itself or
create irreversible financial/security exposure:

- merge of core code when project governance requires it;
- production deploy/rollback;
- production destructive schema operations;
- production secrets/configuration;
- global activation of a real-money rail;
- destructive infrastructure actions;
- paid acquisition spend.

These gates MUST NOT be confused with the customer transaction path.

Once a capability and payment rail are safely enabled by the owner, ordinary
agent transactions proceed without human intervention.

## 10. Execution priority

AION execution priority is:

`make capability executable -> make it discoverable -> make pricing/payment machine-readable -> deploy -> observe real agent traffic -> remove friction -> expand supply/demand -> optimize economics`

Do not block this sequence on optional interviews, outreach replies, manual
participation review or ceremonial proof.

The project advances until a genuine technical, security, legal, funding or
owner-control boundary is reached.

## 11. Definition of launch progress

Launch progress is concrete change in one or more of:

- externally callable production capability;
- machine discovery surface;
- successful agent execution;
- supported machine payment;
- real settlement;
- real revenue;
- positive contribution margin;
- repeat agent use;
- lower execution friction;
- broader qualified supply.

Documentation-only proof work is not launch progress unless it directly removes
a blocker or corrects a material falsehood.

## 12. Final rule

AION exists for agents.

A normal external agent must be able to arrive, understand, request, receive
value, pay when required, verify the result and leave or return later without a
human in the loop.

Build and operate toward that state continuously.
